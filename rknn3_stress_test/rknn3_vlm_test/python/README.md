# 模型裁剪与多设备协同部署说明

## 背景
由于 **RK1820** 等设备的内存资源有限，在部署大规模多模态模型时需要进行适当裁剪，以保证在嵌入式平台上的可用性与推理效率。

## 模型裁剪策略
1. **vision部分**  
   - 在 RK1820 上，由于内存不足，将部分算子（op）迁移至RK3588或其他设备的 CPU 上实现。  
   - 这样既能保留视觉特征提取的完整性，又能避免因资源瓶颈导致的推理失败。

2. **llm部分**  
   - 对于 LLM 的推理，将 LLM Head独立出来，单独在其他设备上运行，从而减少设备内存占用。

3. **完整模型模式（无裁剪）**  
   - 如果是 RK1828 等内存更大的设备，则可直接使用完整模型。  
   - 在使用 Python 导出时，仅需添加以下参数即可启用完整模式：  
     ```bash
     python export_rknn.py --no_prune_mode
     ```

## C++ 部署支持
在 C++ 推理代码中，已经实现了对不同模型格式的自动识别逻辑：  
- 无需修改任何代码，即可兼容裁剪版与完整版模型；  
- 通过内部检测机制，自动选择对应的推理路径。
